## Deviations / Notes

- The spec text in T06 5.2 says "per-axis sigma = CEP / sqrt(2)". A more precise rule for a true 50% CEP is CEP / 1.1774, but the sim follows the explicit spec value (CEP / sqrt(2) ~ 1.06 m).
- The Simulink library `gps_block.slx` wraps `casper_gps_step` via a single MATLAB Function block that declares `coder.extrinsic` on the chain entry point. This is required because `casper_gps_position_model` uses a persistent `RandStream`, which is not Simulink-codegen-friendly but is fully supported in MATLAB-execution / extrinsic mode. The unit tests exercise the underlying .m chain directly (the math), not the Simulink shell, matching the T05 pattern. Full Simulink-level integration is T11.
- Latency test C7 uses a synthetic pos_NED Z-step (100 m) with noise sigmas zeroed so the step is unambiguous in the output.
- The COCOM-exit re-acquire model is idealised (fix 0 -> 2 -> 3 within 1 s); real receivers can take 5-30 s. T06 anti-goal #2 + spec note in 5.5 flag this; Phase 1 may revisit for descent-phase EKF if GPS is used.
- COCOM on/off comparison (C4) tolerates +/-0.25 s to account for the 100 ms output latency plus one 10 Hz sample period of grid quantisation.
- Output streams are int32 / uint8 / logical to match the firmware NAV-PVT struct on the wire (Software/App/drivers/max_m10m.c).
