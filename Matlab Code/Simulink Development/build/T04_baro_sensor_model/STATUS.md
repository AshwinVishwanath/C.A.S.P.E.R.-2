## Round 2 changes vs Round 1

- AC1/AC2/AC3 now run with truth pressure pinned to the t=0 value
  ("stationary pad" mode). R1 used live truth, which sweeps from
  101 kPa down to ~5 kPa over 30 s because the RasAero trajectory
  launches at t=0.025 s; the resulting "noise" was dominated by the
  real altitude change, not the sensor model. Pinning fixes all three.
- AC10 build script: the RateTransition param `DeterministicDataTransfer`
  (which R1's STATUS.md referenced) is not valid in R2025b. The R1
  build code that hit the test bench actually used `OutPortSampleTimeOpt`
  and ran cleanly; R2 verifies this and adds an explicit slx-existence
  check.
- AC11 smoke test: rewritten to drive the standalone `baro_block.slx`
  with a constant-pressure Simulink Bus from a Bus Creator, instead
  of wiring the truth_source library subsystem to the baro_block. The
  R1 path failed because the NoiseModel MATLAB Function block used
  `evalin` + persistent state in a way Simulink could not size at
  compile time. The R2 NoiseModel block declares explicit input/output
  sizes via `assert(isscalar(...))` and uses `coder.extrinsic` for the
  noise function.

## Known low-fidelity model

The Mach-shock model in `casper_baro_mach_shock.m` is a phenomenological piecewise-linear function of Mach and dynamic pressure. It is **not** CFD- or wind-tunnel-calibrated. Its job is to give the EKF Mach gate something to reject. Phase 1 may replace this with a real airframe-specific transonic baro model.
